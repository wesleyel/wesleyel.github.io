Hosting and cataloging 10,000 classic Warcraft III maps

Summer of 2010, at an after-school daycare, I saw Warcraft III for the first time. A classmate was playing Boom Naval Battle and I watched over his shoulder all afternoon.

The next three years of summer and winter breaks went into that game. There were more custom RPG maps on the online platforms than I could ever finish, and my map folder kept growing. I got deep into it — not just playing. I picked up the World Editor, worked out roughly how a .w3x is organized inside, and learned my way around aura effects and ability scripts.

Then I drifted away. Every once in a while I’d open a game with high school friends: Custom Hero World, Crazy Hexagram, the same handful of maps. Over the last few years the battle platforms have opened and shut down in cycles, and the maps we used to play every day are mostly gone. The platforms still running have locked down in-game map sharing, and what’s left is flooded with pay-to-win maps. So the thing I never got around to doing came back: collect the classic maps and build an archive for them. (Special thanks to Bilibili creator 关先生。)

The technical starting point predates that idea by two years. In July 2024, I wanted to know what is actually stored inside a .w3x file.

The map name the game shows you, the author, the recommended player count, the loading screen preview — all of it has to be written somewhere in the file. I started a Rust project called war3parser, spent a month on it, got as far as pulling files out of a map and reading basic information, and then dropped it. I picked it up again in January 2025 for one round of changes, then left it alone for another year and a half. The core rewrite only landed this July.

The parsing half

Code is at war3parser. If you just want to try it, open the browser version and drag a map in.

A Warcraft III map keeps its metadata in a file called w3i, which carries a version number: v8 in the early RoC betas, v33 by WC3 2.0. Fields were appended layer by layer over twenty years. There is no official documentation, and the reverse-engineered tables the community maintains don’t fully agree with each other.

The number of versions is the easy part; you can just transcribe them. The hard part is how old maps are broken. Some have been protected, with the header wiped out entirely. Some have optional sections truncated halfway through. Some don’t even carry a file listing, so you have no idea what’s inside. What the parser has to do is read as much as is still readable, instead of bailing out at the first byte it doesn’t recognize.

I also compiled it to WASM and put up a page where you can drop a map and look at it in the browser, with nothing uploaded. At that point I thought the project was finished.

The 84 GB on my disk

The archiving commands and scripts live in war3-manager, forked from war3parser.

What kept it going was the pile of archives I’d collected.

Map packs pulled from various cloud drives: 17 collections, over ten thousand source files, archives nested inside archives. Filenames carry assorted prefixes and spam, and the same map is stored separately in three different collections. Sitting on a disk like that it does nothing but take up space, and finding a specific map comes down to Finder search plus luck.

So I added a command to the CLI. What it does is fairly dumb: walk every archive recursively, deduplicate by content hash, read the metadata where it parses, pull out the cover image while it’s there, and strip the leftover color codes and unresolved placeholders from map names.

That left 10,365 records. 9,218 with complete information, 858 whose metadata won’t parse but whose files are fine, and 289 campaign packs that are currently only searchable by filename.

The most time-consuming part wasn’t the parsing. It was deciding whether two files count as the same map, and cleaning up those filenames.

A few things in the data

All of these collections are browsable from the site.

The largest category is “Uncategorized”, 5,121 maps, half the archive. Another one I kept verbatim is named “(maps that error out on the official platform)”, 244 of them. That’s the category name whoever organized this pack wrote themselves, and editing it would only lose information.

DotA has 190 versions in here, Guard of Jiange 151, Chenghai 86. Different versions of the same map each get their own record: their content hashes differ, so they really are different files. Scrolling through that list stopped me for a second. I followed those version numbers one release at a time back then, and now they’re lying side by side in a JSON file.

Where the files live

The map files are in a Hugging Face dataset, and the site code is at war3-maps.

The maps are hosted as a Hugging Face dataset. I don’t expect anyone to train a model on them, but nobody knows what AI turns into from here.

On preservation

Most of these maps were made between 2005 and 2012. Author IDs are sitting in the description field; the contact details went dead long ago. Once a cloud drive link expires, or some machine gets scrapped, a map is gone and nobody gets a notification.

I can’t verify the license status of every map one by one. What I can do is keep the content fingerprint and the source path on record, and take something down when someone asks.

I’m not sure how much this matters. Maybe nobody is going to download some tower defense map from 2007 ever again. At least when I go looking for a map now, I don’t have to dig through cloud drives.
